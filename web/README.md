# ツクハコ：ローカルの登録・メール導線

Cの原稿を使い、任意登録→本人確認→初回3通の予定→定期便→解除を試すローカル実装です。Vite / React / TypeScriptとWorkers / ローカルD1で動きます。実メールの送信経路はなく、購入認証も行いません。

## 起動する

A・B・Cを合わせたbranchで、nvmのNode 24系を選んだシェルを使います。最初のコマンドはリポジトリ直下で実行してください。

```sh
npm ci --prefix web
cd web
npm run dev
```

[ローカルプレビュー](http://127.0.0.1:5173/preview)を開きます。APIは `127.0.0.1:8787` です。起動時に `../docs/launch/` の原稿を取り込み、ローカルD1のmigrationを適用してから両サーバーを起動します。Cloudflareのログインや本番DBは不要です。`wrangler.jsonc` のDB IDはローカル用の仮値で、`remote: false` です。[D1のローカル開発](https://developers.cloudflare.com/d1/best-practices/local-development/)。

他の起動と重なる場合は、`web/` で次を使います。統合検証もこの組合せを使っています。

```sh
WEB_PORT=5183 API_PORT=8797 npm run dev
```

この場合は [5183のプレビュー](http://127.0.0.1:5183/preview) です。担当別worktreeからC原稿を読む場合だけ、`CONTENT_ROOT` にその `docs/launch` の絶対パスを指定します。設定例は [.env.example](.env.example) にありますが、`dev.mjs` のポートと原稿パスは起動時の環境変数で渡してください。`.env` をコピーするだけでこれらが読み込まれることは前提にしていません。

終了は、起動したターミナルでCtrl+Cです。ローカルDBは `web/.wrangler/state/`、取込済み原稿は `web/.generated/` に残ります。再起動後は同じ試用状態を引き継ぎ、別worktreeでは別のDBになります。最初から試すなら、停止後にこの `web/.wrangler/` だけを未使用の別名へ退避して起動します。アプリ、Docker、ほかのworktreeのデータを削除する必要はありません。

## 架空読者で一周する

1. `/preview` の「共通フッター・送信元・リンク・配信条件」と各原稿を開き、件名・本文・対象・リンクを読みます。confirmとwelcome-01〜03を「原稿をローカル確認」→「ローカル試用で有効化」にします。定期便は後の手順で予約します。
2. `/mail` へ進み、`reader@example.test` を入力し、内容・頻度への同意にチェックして登録します。実在する宛先は使いません。APIも `.test` / `.invalid` / `example.com` の架空宛先だけを受け付けます。
3. `/preview` のローカル受信箱から確認メールのHTMLを開き、確認リンクへ進みます。ページを開くだけでは確定しません。「登録を確定する」で初回3通の予定ができます。
4. `/preview` に戻り「予定分をMockで処理する」を押します。初回1通目のHTMLとガイドへのリンクを確認できます。`accepted` はMockの受付で、実到達を意味しません。
5. 下の表を参考に、仮想時計を2日後・5日後へ進め、その都度Mock処理します。いきなり7日後へ飛ばすと、古い便が許容遅延を超えて見送られることがあります。
6. 確認後7×24時間以上経過し、初回が処理済みになったら、broadcast-001をローカル確認し、「現在の仮想日時で号を予約」→Mock処理します。未確認アドレスや初回未処理の人は対象外です。
7. 学習メールHTMLの「配信を停止する」リンクを開き、停止ボタンを押します。ログインは不要です。再び購読する場合はフォームで同意し、新しい確認メールを確定します。

新しいDBの仮想時計は **2026-10-22 19:00 JST** です。その時点で確認した場合の例です。日付入力欄はUTCなので、次の値を入力します。すでに時計を進めている場合は、実際の確認日と予定一覧を使ってください。

| 予定 | 仮想時計への入力（UTC） | 日本時間 |
|---|---|---|
| 初回1通目 | 初期値 `2026-10-22T10:00:00.000Z` | 10月22日19:00 |
| 初回2通目 | `2026-10-24T10:00:00.000Z` | 10月24日19:00 |
| 初回3通目 | `2026-10-27T10:00:00.000Z` | 10月27日19:00 |
| 定期便001の試用 | `2026-10-29T10:00:00.000Z` | 10月29日19:00 |

**予約後の解除も確認する場合：** 時計を進める前に、別の `stop@example.test` で手順2〜4を行い、初回1通目の解除リンクから停止します。この読者の初回2/3通目が抑止され、継続用のreaderの予定は残ることを確認できます。

ローカルの確認操作は試作DBだけに適用します。CのMarkdownはdraftのまま、本番の承認にはなりません。Brain・窓口・プライバシーの未設定URLは「設定待ち」と表示し、実在しそうなダミーURLにはしません。

## 未着・再送・停止・改稿を試す

- 確認リンクは24時間有効です。未着画面から再送すると、前の未使用リンクを失効させます。再送で元の同意日時は変えません。現在の仮値は60秒間隔、宛先ごとにJSTの1日5要求、ローカルアクセス元全体で1時間20要求までで、連打も数えます。
- 「受付後タイムアウトを試す」は、Mock受信箱に受付記録がある一方で配送状態が `unknown` になる例です。自動再送せず、「Mock受付記録と照合する」で同じ配送を照合します。
- 初回と定期の合計はJSTの暦日1通。`submitting` / `unknown` も日次枠を保持し、確認メールは別枠です。48時間を超えて遅れた便は `skipped` になり、まとめて送りません。仮値は [public-settings.json](config/public-settings.json) のrulesにあります。
- 「全体停止・未送信予定を取り消す」は新規受付と未受付の予約・失敗分を止め、予約中の定期号も退役させます。停止解除で旧予約は復活しません。すでにMockで受け付けた記録は残ります。
- 原稿・フッター・設定・参照ガイドを変えたら、`npm run content` を実行するかdevを再起動します。新revisionはdraftになり、旧版の未受付予定を取り消します。共通原稿は再確認→有効化、定期号は再確認→予約の後、「改稿で止めた予定をこの版へ振り替える」で対象を明示します。改稿による未受付取消だけが対象です。解除/全体停止で止めた予定は復活せず、同じ号の受付済み配送は増えません。

## 検査する

`web/` で実行します。

```sh
npm test
npm run build
npm run check:release
```

`npm test` はMiniflareのWorkers / ローカルD1で架空データを使う試験です。GET先読み、重複、日付境界、解除、改稿、受付不明、停止競合などを検査します。本番サービスの検証ではありません。最新の結果は [REPORT.md](REPORT.md) を参照してください。

`npm run build` は原稿取込・型検査・静的UIビルドと混入検査です。`web/dist/` からpreview管理や有料受取キー等を除きますが、**試作の静的資材を確認するビルドであり、本番公開可能という意味ではありません**。dist単体には利用可能な本番APIがありません。

`npm run check:release` は現状では **終了コード1が期待結果** です。未設定リンク・送信者、未承認原稿、内部メモ、実送信アダプター未実装を理由に本番出力を拒否します。nullを埋めたりAPIキーを追加したりしても、実メールへ切り替わる機能はありません。

## 原稿と外部サービスの境界

`npm run content` はCのメール5本、2フッター、4公開ガイド、公開リンク用途、画面文言だけを明示的に取り込みます。`brain-paid.md` と `PRIVATE-LINKS.example.json` は読みません。未知変数・非公開リンクキーも拒否します。固定値の設定先は [public-settings.json](config/public-settings.json)、原稿契約は [Cレポート](../docs/launch/REPORT.md) です。

確認/解除tokenの照合テーブルにはハッシュだけを保存します。ローカル受信箱はクリック試験のため、架空メール本文と受信者別URLを保存するので、`.wrangler/` や `.generated/` をGitや公開資材へ追加しません。実名簿・APIキー・実際の `.env` は使いません。

`/api/preview/*` と `/api/mail-events` はローカル試用専用です。後者はfixtureイベントの入口で、本番webhookの署名検証は未実装です。解除のform POST契約も、HTTPS/DKIMを含む本番ワンクリック解除の完了を意味しません。非localhost・非previewのリクエストは拒否します。

次の準備は [PROVIDER-SETUP.md](PROVIDER-SETUP.md)、本人が決める項目と未確認は [PUBLISH-CHECKLIST.md](PUBLISH-CHECKLIST.md) にまとめています。
