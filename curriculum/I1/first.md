# SQLで調べるデータベース：SQLでサンプルデータを確認する

プロジェクトのファイルができました。コンテナーはまだ起動していません。今回の到達点は「SQLでサンプルデータを確認する」です。ソースの編集・復元は、そのあとに選べる[任意の練習](#任意の練習)です。

教材の閲覧とファイル生成はネット接続なしで行えます。初回起動のイメージ・依存取得にはネット接続が必要です。

## 今回のプロジェクト

保存先：

```text
/home/your-name/projects/sample
```

構成：SQLで調べるデータベース

.envと.devcontainerは生成済みです。READMEの手動設定をやり直す必要はありません。

DBの接続先：`localhost:55432`。SQLの操作は、下記のコンテナー内ターミナルで行います。

1. [準備を確認する](#準備を確認する) — このフォルダーで設定とDockerを確認します。エラーがあれば、対処してから進みます。
2. [VS Codeでフォルダーを開く](#vs-codeでフォルダーを開く) — VS Codeで今回の保存先を開きます。信頼の確認が出た場合は、このフォルダーだけを確認して信頼します。
3. [コンテナーで開く](#コンテナーで開く) — 未接続なら通知の「Reopen in Container」を選びます。通知がなければCtrl+Shift+Pから「Dev Containers: Reopen in Container」。このフォルダーのコンテナーに接続済みなら次へ進みます。
4. [初期処理の正常終了を待つ](#初期処理の正常終了を待つ) — 構成ターミナルの「PASS: otoka_learning / PostgreSQL」に続くバージョンと、初期処理の正常終了を確認します。処理中・エラー時は次へ進みません。
5. [サンプルデータを準備する](#サンプルデータを準備する) — 新しいターミナルでサンプルデータを準備します。pwdが/workspaceであることを確認します。
6. [SQLの主要操作を確認する](#sqlの主要操作を確認する) — サンプルDBでSQLの主要操作を確認します。試験内の変更は元へ戻ります。
7. [サンプルの動作を確認する](#サンプルの動作を確認する) — 下のコマンドで、用意したサンプルデータをSQLで検索します。

まず次をコピーして実行し、このプロジェクトへ移動します。

```sh

pwd
```

pwdの結果が上の保存先と一致すれば、作業する場所は正しく開けています。以降のホスト用コマンドも、このフォルダーで実行します。

下のコマンドで、このフォルダーの設定とDockerへの接続を確認します。.envと.devcontainerは生成済みです。作り直す必要はありません。不足がある場合は[準備が足りないとき](#準備が足りないとき)、Dockerのエラーは[Dockerにつながらないとき](#dockerにつながらないとき)へ進み、対処後にこのコマンドをもう一度実行します。

```sh
'bash' 'scripts/doctor.sh'
```

確認できる結果：PASS: Docker / Compose / 設定 が表示されます。これは設定の確認で、DB接続は後の手順で確認します。

場所：VS Codeの編集画面。このプロジェクトのフォルダーで行います。

VS Codeを起動し、「ファイル」→「フォルダーを開く」（File → Open Folder）で、上の保存先を開きます。 信頼の確認が出たら、保存先が自分で生成したフォルダーであることを確認して信頼します。「Restricted Mode」（制限モード）が表示される場合も、そのフォルダーだけを確認して信頼します。ローカル学習にVS Codeのサインインは不要です。

確認できる結果：VS Codeのエクスプローラーに、このフォルダーのSTART_HERE.mdとREADME.mdが表示されます。

## コンテナーで開く

場所：VS Codeの編集画面。このプロジェクトのフォルダーで行います。

未接続なら通知の「Reopen in Container」を選びます。通知がなければCtrl+Shift+Pでコマンドパレットを開き、「Dev Containers: Reopen in Container」を検索して選びます。このフォルダーのコンテナーに接続済みなら、開き直さず次へ進みます。初回はイメージの取得と環境の作成を待ちます。コマンドがない場合は[準備が足りないとき](#準備が足りないとき)へ進みます。

## 初期処理の正常終了を待つ

場所：VS Codeの編集画面。このプロジェクトのフォルダーで行います。

VS Codeの構成ターミナル（Configuring... など）を開き、本文の「PASS: otoka_learning / PostgreSQL」に続くバージョンと、Doneの表示など初期処理がエラーなく正常終了したことの両方を確認します。接続バッジ・node_modulesの存在・タブ名だけでは判断しません。処理中は別のコマンドを重ねず、そのまま待ちます。進まない場合や失敗時は[初期処理が終わらないとき](#初期処理が終わらないとき)へ進みます。

確認できる結果：構成ターミナルに「PASS: otoka_learning / PostgreSQL」に続くバージョンが表示され、初期処理が正常終了しています。

## 同じフォルダーから再開する

同じプロジェクトを生成し直さず、上の保存先を使います。次回も[VS Codeでフォルダーを開く](#vs-codeでフォルダーを開く)から既存フォルダーを開き、START_HERE.mdを開きます。VS Codeのプレビューはファイルを右クリックして「Open Preview」（プレビューを開く）で表示できます。.envと.devcontainerはそのまま使います。

[準備を確認する](#準備を確認する)で設定とDockerを再確認し、[コンテナーで開く](#コンテナーで開く)へ進みます。初期処理が始まった場合は[初期処理の正常終了を待つ](#初期処理の正常終了を待つ)で正常終了を確認します。初回の正常終了を確認済みで、再開時に初期処理が実行されなければ、[サンプルの動作を確認する](#サンプルの動作を確認する)から続けます。

## 準備が足りないとき

PC側のVS CodeにMicrosoftのDev Containers（ms-vscode-remote.remote-containers）拡張が必要です。左側の「拡張機能」で名前と発行元を確認します。DockerとComposeも、PC側で利用できる必要があります。生成済みの.devcontainerとは別の準備です。

[導入の補助資料](docs/setup.md)のLinuxの項目を確認してください。設定ファイルを作り直す必要はありません。準備後は[準備を確認する](#準備を確認する)へ戻ります。

## Dockerにつながらないとき

場所：Linuxのターミナル。このプロジェクトのフォルダーで行います。

```sh
'docker' 'version'
'docker' 'compose' 'version'
```

docker versionのClientとServerの両方が表示されることを確認します。Serverへ接続できない場合は、Dockerの起動状態と通常ユーザーの利用権限をPCの導入手順に沿って確認します。

接続できたら[準備を確認する](#準備を確認する)へ戻ります。

## 初期処理が終わらないとき

VS Codeの構成ターミナルとDev Containersのログを開きます。ログが進んでいれば、初回の取得・構成処理を待ちます。失敗した場合は、最後のエラーとネット接続、空き容量を確認します。処理中に別のnpm ciなどを重ねて実行しません。

[初期処理の復旧資料](docs/recovery.md)を参照する場合も、生成済みの.envは作り直しません。初期処理を再実行した後は[初期処理の正常終了を待つ](#初期処理の正常終了を待つ)へ戻り、表示と正常終了の両方を確認します。

## サンプルを確認できないとき

DBのエラーは[接続とSQLの復旧資料](docs/troubleshooting.md)で確認します。初回にテーブルがない場合は、この案内の「サンプルデータを準備する」が正常終了したか確認します。復旧後は[サンプルの動作を確認する](#サンプルの動作を確認する)のSQLを再実行します。
