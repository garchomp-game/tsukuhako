# 入力と表示のWeb画面：サンプル画面を表示する

プロジェクトのファイルができました。コンテナーはまだ起動していません。今回の到達点は「サンプル画面を表示する」です。ソースの編集・復元は、そのあとに選べる[任意の練習](#任意の練習)です。

教材の閲覧とファイル生成はネット接続なしで行えます。初回起動のイメージ・依存取得にはネット接続が必要です。

## 今回のプロジェクト

保存先：

```text
/home/your-name/projects/sample
```

構成：入力と表示のWeb画面

.envと.devcontainerは生成済みです。READMEの手動設定をやり直す必要はありません。

## 準備を確認する

場所：Linuxのターミナル。このプロジェクトのフォルダーで行います。

まず次をコピーして実行し、このプロジェクトへ移動します。

```sh
cd -- '/home/your-name/projects/sample'
pwd
```

pwdの結果が上の保存先と一致すれば、作業する場所は正しく開けています。以降のホスト用コマンドも、このフォルダーで実行します。

下のコマンドで、このフォルダーの設定とDockerへの接続を確認します。.envと.devcontainerは生成済みです。作り直す必要はありません。不足がある場合は[準備が足りないとき](#準備が足りないとき)、Dockerのエラーは[Dockerにつながらないとき](#dockerにつながらないとき)へ進み、対処後にこのコマンドをもう一度実行します。

```sh
'bash' 'scripts/doctor-host.sh'
```

確認できる結果：診断OK と、このプロジェクトのURLが表示されます。これは起動前の確認で、サンプルはまだ動いていません。

## VS Codeでフォルダーを開く

場所：VS Codeの編集画面。このプロジェクトのフォルダーで行います。

VS Codeを起動し、「ファイル」→「フォルダーを開く」（File → Open Folder）で、上の保存先を開きます。 信頼の確認が出たら、保存先が自分で生成したフォルダーであることを確認して信頼します。「Restricted Mode」（制限モード）が表示される場合も、そのフォルダーだけを確認して信頼します。ローカル学習にVS Codeのサインインは不要です。

確認できる結果：VS Codeのエクスプローラーに、このフォルダーのSTART_HERE.mdとREADME.mdが表示されます。

## コンテナーで開く

場所：VS Codeの編集画面。このプロジェクトのフォルダーで行います。

Ctrl+Shift+Pでコマンドパレットを開き、「Dev Containers: Reopen in Container」を検索して選びます。初回はイメージの取得と環境の作成を待ちます。コマンドがない場合は[準備が足りないとき](#準備が足りないとき)へ進みます。

確認できる結果：VS Code左下にDev Containerへの接続が表示され、/workspaceのファイルが開きます。接続表示だけでは初期処理の完了ではありません。

## 初期処理の正常終了を待つ

場所：VS Codeの編集画面。このプロジェクトのフォルダーで行います。

VS Codeの構成ターミナル（Configuring... など）を開き、本文の「準備完了」と、Doneの表示など初期処理がエラーなく正常終了したことの両方を確認します。接続バッジ・node_modulesの存在・タブ名だけでは判断しません。処理中は別のコマンドを重ねず、そのまま待ちます。進まない場合や失敗時は[初期処理が終わらないとき](#初期処理が終わらないとき)へ進みます。

確認できる結果：構成ターミナルに「準備完了」が表示され、初期処理が正常終了しています。

## 開発サーバーを起動する

場所：VS CodeのDev Container内ターミナル。/workspaceで行います。

初期処理の正常終了を確認してから、VS Codeの「ターミナル」→「新しいターミナル」で実行します。pwdが/workspaceであることを確認します。このターミナルを動かしたまま、次へ進みます。next: not foundなどが出た場合は[初期処理が終わらないとき](#初期処理が終わらないとき)へ戻ります。

```sh
'npm' 'run' 'dev'
```

確認できる結果：VITE と Local のURLが表示されます。次の確認には、この案内のURLを使います。

## 終了する

場所：開発サーバーを動かしているVS CodeのDev Container内ターミナル。Ctrl+Cでサーバーを止めます。コマンドを入力できる状態へ戻ったことを確認します。

ファイルを保存して、このプロジェクトのVS Codeウィンドウを閉じます。次はLinuxのターミナル。このプロジェクトのフォルダーで行います。

```sh
cd -- '/home/your-name/projects/sample'
pwd
```

```sh
'bash' 'scripts/compose.sh' 'stop'
```

各コマンドがエラーなく終了したことを確認します。これは通常の停止です。ソースやDBのデータを消す操作は行いません。

## 同じフォルダーから再開する

同じプロジェクトを生成し直さず、上の保存先を使います。次回も[VS Codeでフォルダーを開く](#vs-codeでフォルダーを開く)から既存フォルダーを開き、START_HERE.mdを開きます。VS Codeのプレビューはファイルを右クリックして「Open Preview」（プレビューを開く）で表示できます。.envと.devcontainerはそのまま使います。

[準備を確認する](#準備を確認する)で設定とDockerを再確認し、[コンテナーで開く](#コンテナーで開く)へ進みます。初期処理が始まった場合は[初期処理の正常終了を待つ](#初期処理の正常終了を待つ)で正常終了を確認します。初回の正常終了を確認済みで、再開時に初期処理が実行されなければ、[開発サーバーを起動する](#開発サーバーを起動する)から続けます。

## 準備が足りないとき

PC側のVS CodeにMicrosoftのDev Containers（ms-vscode-remote.remote-containers）拡張が必要です。左側の「拡張機能」で名前と発行元を確認します。DockerとComposeも、PC側で利用できる必要があります。生成済みの.devcontainerとは別の準備です。

[導入の補助資料](docs/SETUP.md)のLinuxの項目を確認してください。設定ファイルを作り直す必要はありません。準備後は[準備を確認する](#準備を確認する)へ戻ります。

## Dockerにつながらないとき

場所：Linuxのターミナル。このプロジェクトのフォルダーで行います。

```sh
'docker' 'version'
'docker' 'compose' 'version'
```

docker versionのClientとServerの両方が表示されることを確認します。Serverへ接続できない場合は、Dockerの起動状態と通常ユーザーの利用権限をPCの導入手順に沿って確認します。

接続できたら[準備を確認する](#準備を確認する)へ戻ります。

## 初期処理が終わらないとき

VS Codeの構成ターミナルとDev Containersのログを開きます。ログが進んでいれば、初回の取得・構成処理を待ちます。失敗した場合は、最後のエラーとネット接続、空き容量を確認します。処理中に別のnpm ciなどを重ねて実行しません。

[初期処理の復旧資料](docs/RECOVERY.md)を参照する場合も、生成済みの.envは作り直しません。初期処理を再実行した後は[初期処理の正常終了を待つ](#初期処理の正常終了を待つ)へ戻り、表示と正常終了の両方を確認します。

## サンプルを確認できないとき

開発サーバーのターミナルにエラーがないか確認します。停止していたら[開発サーバーを起動する](#開発サーバーを起動する)へ戻ります。初期処理を終えていなければ[初期処理の正常終了を待つ](#初期処理の正常終了を待つ)から続けます。

[サンプルの動作を確認する](#サンプルの動作を確認する)のURLまたはコマンドをそのまま使います。別の保存先や古いポート、127.0.0.1に置き換えないでください。直らない場合は[停止・復旧の補助資料](docs/RECOVERY.md)を確認してください。
