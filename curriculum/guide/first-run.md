# サンプル画面を表示する

[はじめて使うに戻る](START_HERE.md) · Windows / Linux x64 · ツクハコ1.0.2 · ガイド2026-10-25-r10

**準備を確認する → 新しいフォルダーを作る → VS Codeで開く → 初期処理を待つ → サンプル画面を見る**、の順に進めます。ツクハコの作成画面にある4段階は、このうちフォルダーを作るまでの手順です。

## 準備を確認する

ツクハコ上部の **「作る」** を押し、**「準備を確認する」** を見ます。ファイルの作成に必要な条件と、作ったものを動かす前に必要な条件を確認します。

使っているOSの準備手順を開き、不足している項目だけ進めます。

- **Windows:** [Windows / WSL 2の準備](lesson:setup/windows)。通常ユーザーのWSL 2を用意し、ツクハコで開発するWSLを選んで **「WSL用ファイルを準備」** を押します。Docker DesktopのWSL Integrationと、Windows側のVS Code・WSL拡張・Dev Containers拡張を確認します。
- **Linux:** [Linuxの準備](lesson:setup/linux)。Docker・VS Code・Dev Containers拡張を確認します。ファイル作成の条件がそろっていれば、Dockerなどの準備より先にファイルを作れます。

**結果の確認：** 必要な導入・起動・再ログインを終えたら、ツクハコの開発準備チェックで **「もう一度確認」** を押します。「利用可能」などの結果と診断時刻を確認します。確認できない項目は、導入済みとも未導入とも決めつけず、その項目の案内を開きます。

準備チェックはコンテナーの起動やサンプル表示を行いません。その操作はフォルダーを作った後に行います。

## 新しいフォルダーを作る

最初の画面では **「手順を見ながら進める」** と **「必要な操作だけ進める」** を選べます。作るファイルと接続先は同じです。生成後の手順でも切り替えられます。

1. ツクハコの「作る」で **「はじめてのWeb画面で始める」** を押します。推奨構成が選ばれます。WindowsでWSLの準備が必要な場合は先に画面の案内で準備を済ませ、**「保存先を決める」** を押します。**「プロジェクトの置き場所を決めます。」** と表示されたら保存先の入力画面です。
2. **「親フォルダ」** に、すでに存在する自分が書き込める場所を指定します。Windowsでは選択したWSLの `/home/…` または `~/` を入力します。Cドライブは使いません。**「新しいフォルダ名」** には `web-first` など、まだ存在しない名前を入力します。すでに作っている場合は、[同じプロジェクトを再開する](TROUBLESHOOTING.md#同じプロジェクトを再開する)へ進みます。
3. **「作成内容を確認」** を押し、構成名と保存先を確認します。詳細設定は、変更する必要がある場合だけ開きます。ポートが使用中なら、[使うポートを変更する](TROUBLESHOOTING.md#使うポートを変更する)へ進みます。
4. **「プロジェクトを作成」** を押します。

途中で準備を見直す場合は **「準備の状態を確認」** を開きます。**「作成に戻る」** で入力の続きへ戻れます。別の構成を選ぶときは **「← 戻る」** を押します。

**結果の確認：** ファイルの作成完了と、今回の保存先が表示されます。コンテナーやサンプルは、まだ起動していません。生成済みの `.env` を作り直す必要はありません。

作成できない場合は、[保存先を確認する](TROUBLESHOOTING.md#保存先を確認する)へ進みます。

## 今回の手順を開く

作成結果の **「サンプル画面を表示する手順へ」** を押します。ここからは、**今回の保存先・コマンド・URLが入った手順**を使います。簡潔な表示でも必要な準備と正常終了の確認は残ります。「詳しい確認方法」から説明を開き、「簡潔な手順に戻る」で戻れます。保存・コピーする手順には復旧方法も含まれます。別の教材から値を転記したり、URLをメモしたりする必要はありません。

その手順にあるホスト用のコマンドは、**Windowsでは選択したWSLのターミナル、LinuxではPCの通常のターミナル**で実行します。PowerShellやDev Container内のターミナルではありません。最初に示された `cd --` から始まるコマンドで今回のフォルダーへ移動し、プロジェクトの準備診断を実行します。

**結果の確認：** 現在のフォルダーが手順の保存先と一致し、診断に **「診断OK」** が表示されます。不足が表示されたら[準備を確認する](#準備を確認する)へ戻ります。

## VS Codeでフォルダーを開く

**「今回使うフォルダーと接続先」のすぐ下にある「このフォルダーをVS Codeで開く」** を押します。VS Codeで開いたフォルダーが今回の保存先であることを確認します。信頼の確認が出た場合は、自分が生成したそのフォルダーを確認して信頼します。

**結果の確認：** VS Codeに今回のフォルダーが開き、`START_HERE.md` が見えます。開けない場合は[VS Codeで今回のフォルダーを開く](TROUBLESHOOTING.md#vs-codeで今回のフォルダーを開く)へ進みます。

## コンテナーで開く

VS Codeで `Ctrl+Shift+P` を押し、**「Dev Containers: Reopen in Container」** を検索して選びます。開発環境の設定を新しく作る操作は不要です。

**途中の目印：** VS CodeにDev Containerへの接続が表示され、作ったファイルが開きます。接続だけでは初期処理は完了していません。次の確認へ進みます。

コマンドが見つからない場合は、[Windowsの拡張機能](lesson:setup/windows#vs-codeへ必要な機能を追加する)／[Linuxの拡張機能](lesson:setup/linux#vs-codeへ必要な機能を追加する)を確認します。

## 初期処理の正常終了を待つ

VS Codeの **「表示」→「ターミナル」** を開き、初期構成用のタブ（`Configuring...` など）を選びます。初回は必要なファイルの取得と処理を待ちます。

**次へ進める目印は、本文に「準備完了」があり、初期構成処理がエラーなく正常終了していることの両方です。** 接続表示、タブ名、`node_modules` の存在だけでは判断しません。

処理中は別の `npm ci` を実行せず、そのまま待ちます。進まない場合は[初期処理の状態を確認する](TROUBLESHOOTING.md#初期処理が終わらない)、エラーで終わった場合は[原因を確認して初期処理をやり直す](TROUBLESHOOTING.md#初期処理が失敗した)へ進みます。

## 開発サーバーを起動する

初期処理の正常終了後に、VS Codeの **「ターミナル」→「新しいターミナル」** を開きます。`pwd` を実行し、**`/workspace`** と表示されることを確認してから、同じターミナルで起動します。

```sh
npm run dev
```

**結果の確認：** ターミナルに **`Ready`** が表示されます。このターミナルは動かしたまま、次へ進みます。

## サンプルの動作を確認する

OSのブラウザーで**今回の手順にあるURL**を開きます。起動ログに出た別のポートへ置き換えません。

**結果の確認：** サンプル画面に **「小さく変えて、動きを確かめよう。」** と表示されます。

## 初回完了

自分でサンプルの見出しを確認できたら、初回の目標は達成です。

表示できない場合は[サーバーとURLを確かめる](TROUBLESHOOTING.md#画面が表示されない)へ進みます。今日は終える場合は[作業を終える](TROUBLESHOOTING.md#作業を終える)、続けたい場合だけ[文字の変更・復元を試す](NEXT-STEP.md)を開きます。

## 終了する

今日はここで終える場合は、[サーバーとコンテナーを止める](TROUBLESHOOTING.md#作業を終える)手順を使います。ツクハコを閉じるだけでは止まりません。

## 同じフォルダーから再開する

次回は[前に作成したフォルダーを開いて再開](TROUBLESHOOTING.md#同じプロジェクトを再開する)します。アプリを閉じた後も、作成したフォルダーの `START_HERE.md` から今回の手順を読めます。
