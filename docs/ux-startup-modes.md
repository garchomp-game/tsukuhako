# 生成後の操作と案内モード

## 目的と画面順序

生成直後に「何を開くか」「どこへ接続するか」を見せ、説明の長さを利用者が選べるようにする。

1. 今回のフォルダーと接続先
2. 「このフォルダーをVS Codeで開く」と「保存先をコピー」
3. 構成・到達点のタイトル
4. 案内の詳しさの選択と手順

VS Codeを開く操作は既存の検証済みIPCを使う。表示側から任意のパスを渡さず、直近の生成結果だけを対象にする。開いたこととサンプルが起動したことを区別する。失敗時は実際の保存先、手動で開く方法、準備へのリンクを表示する。

## 二つの進め方

| 選択 | 主な表示 | 共通で維持すること |
| --- | --- | --- |
| 手順を見ながら進める（既定） | 背景、操作、確認方法、復旧、任意の練習 | プロジェクト・ポート・必須操作・正常終了の条件 |
| 必要な操作だけ進める | 必須操作、コマンド、期待する結果。教材の目次は必要時に開く | 同上。確認を飛ばすモードではない |

最初の画面と生成後の手順で選べる。設定は読書位置と同じローカル設定へ保存し、旧設定では詳しい表示を使う。モード変更でプロジェクト、入力、接続先、VS Code操作の失敗情報を破棄しない。

簡潔な手順から詳細・停止・再開・復旧へのリンクを押したときは、詳細本文を表示して対象見出しへ移動する。「簡潔な手順に戻る」で元の表示へ戻れる。ヘルプ往復でも選択を保持する。

## 一つの手順データ

二つの表示は共有の `nextSteps` を使う。必須操作に短い説明を持たせ、簡潔な表示と保存するSTART_HERE.mdの操作一覧に利用する。保存・コピー版は復旧を含む完全な手順を保持する。

- S2ではローカルDB起動をコンテナーで開き直す前に残す。
- I1ではSQLの準備・確認・検索を残し、Web用のコマンドやURLを表示しない。
- Windowsでは生成したWSLを対象にする。
- 接続バッジだけで完了とせず、初期処理の正常終了を確認する。
- 手動診断は今回省略しない。自動診断との統合は構成別の失敗経路を確認した後に判断する。

## 同時に改善する点

接続先の用途を「起動後にブラウザーで開くURL」「起動後に確認するAPIのURL」「DBの接続先」で区別する。内部のポート一覧は詳細へ置く。外側だけ番号が異なるときに限り、ターミナルの3000との違いを説明する。

通知が出ないときのコマンドパレット、既に接続済みの場合、信頼の確認が出た場合を分ける。狭い画面とキーボードでも主操作へ到達でき、モード切り替え後の焦点とリンク先が失われないことを確認する。

## 公開前の残件

今回の配布候補はローカルで作成・検証する。外部公開、main統合、Windows通常ユーザーの実WSL確認は別の作業。

追加候補は、使用中ポートの自動選択と既存プロジェクトの再設定、再起動後に作成済みプロジェクトを選び直す入口。既存設定・データの保持、表示と保存ガイドの同時更新、同時起動の競合を設計してから実装する。現在は競合診断と手動設定、保存先のSTART_HERE.mdからの再開を使う。
