# 最初の設定を、もう一度書かなくていいようにする

環境を作るとき、選んだ設定を別のファイルへ書き写す操作があります。保存先やポートを決めたのに、次の手順でまた同じ値を入れる。小さなことでも、別の値を入れてしまうきっかけになります。

ツクハコでは、新しいプロジェクトを生成するときに `.env` も作ります。ここではF2を例に、この一つの工夫を紹介します。

## 生成時の設定を、そのまま案内へ渡す

F2の生成では、アプリで決めたポートなどを `.env` に保存し、同じポートと保存先を `START_HERE.md` に載せます。生成後に、案内の標準ポートを見ながら `.env` を最初から作り直す必要はありません。

開発を始めるときは、生成先の `START_HERE.md` を開いてください。「このプロジェクトの設定」にあるポートと、後ろのブラウザ用URLを確認できます。別の教材にある標準値よりも、そのプロジェクトの案内を使います。

減らしたのは、最初の設定を別の場所へもう一度書く操作です。DockerやVS Codeの準備、初回のファイル取得、初期構成の正常終了の確認は引き続き必要です。ファイルができた段階では、コンテナはまだ起動していません。

## 後から設定を変えたときは

`START_HERE.md` は生成時の案内です。生成後に `.env` のポートなどを手動で変更しても、この案内が自動更新されるわけではありません。設定を変更するときは、生成先の `docs/RECOVERY.md` で再構築の手順を確認し、案内に残っている値との違いもメモしてください。

`.env` の中には、構成によってパスワードなどが入ります。内容をそのまま問い合わせや公開記事に貼る必要はありません。

この生成処理は0.4.4の実装に含まれています。F2の生成から起動・変更・復元・再開は、Linux Mint 22.3の既存開発環境で確認した範囲です。すべてのPCで準備が不要になるという意味ではありません。

今度自分の手順を見るときも、「同じ値をもう一度入力している場所」が一つないか、探してみてください。
