# 「開いた」と「準備が終わった」を分けて確認する

ツクハコでファイルを生成できた状態、Dockerを使える状態、開発環境が起動した状態は、それぞれ違います。途中で止まったときは、今いる場所を確認すると、戻る手順を選びやすくなります。

ここではF2（Next.js + TypeScript + Tailwind）を例にします。0.4.4の一連の操作は、Linux Mint 22.3 x64の既存開発環境で確認しています。Windows 11実機や、何も導入していないPCでの完走を確認したガイドではありません。別の構成では、生成先の `START_HERE.md` を優先してください。I1はDB用の手順です。

## まず、三つだけメモする

1. 何をしようとしていたか。
2. 最後にできた操作は何か。
3. どの画面に、どんな表示が出ているか。

「F2を生成し、VS Codeで開いた。構成ターミナルに依存ファイルを取得している表示がある」のように書ければ十分です。

## F2の準備を順番に確かめる

アプリの「作る」で準備チェックを確認します。不足がある場合はOS別の教材へ戻り、用意した後に「もう一度確認」を押します。古い診断結果は、今の状態を保証しません。

生成先の `START_HERE.md` を開き、その保存先・ポートを使います。生成時点で `.env` は作成済みなので、最初から作り直す必要はありません。ホスト側のターミナルで、そのプロジェクトのフォルダに移動してから次を実行すると、診断結果とこのプロジェクトのURLを確認できます。

```sh
bash scripts/doctor-host.sh
```

Windowsの案内では「ホスト側」は選んだWSL内を指します。PowerShellやDev Container内へ、同じコマンドを順番に試す手順ではありません。

VS Codeで「Dev Containers: Reopen in Container」を実行したら、構成ターミナル（Configuring... など）を開きます。本文の **「準備完了」** と、初期構成処理がエラーなく正常終了したことの両方を確認してください。

左下の接続表示、`node_modules` の存在、タブの名前だけでは完了と判断しません。処理中は、別の `npm ci` を重ねて実行せず、そのまま待ちます。

正常終了後に新しいDev Container内ターミナルを開き、`pwd` が `/workspace` と表示されることを確認して、次を実行します。

```sh
npm run dev
```

`Ready` が出たら、ブラウザで `START_HERE.md` のURLを開きます。教材にある標準ポートへ置き換えず、自分が生成したプロジェクトの値を使ってください。

## 止まった場合に戻る場所

早く実行して `next: not found` が出た場合は、初期構成の正常終了を確認してから `npm run dev` を再実行します。構成処理そのものが失敗している場合は、構成ターミナルのログと、生成先の `docs/RECOVERY.md` を確認してください。

画像やログを共有するときは、パスワード、APIキー、`.env` の中身や個人用のパスが含まれていないか確認します。

画面が動いたら、[F2の最初の変更と復元]({{links.exerciseGuide}})へ進めます。まだ準備中なら、この三つのメモを残すところで区切って構いません。
