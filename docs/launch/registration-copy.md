# 登録・確認・解除の画面文言（制作向け）

本文用の文言は [screen-copy.json](screen-copy.json) が正本です。この文書自体は公開ページへ貼りません。`schemaVersion: 1`、同意の版は `2026-10-22-v1`。送信者は `senderName` / `senderContact`、リンクは用途キーで解決します。実URL・メールアドレス・トークンはここへ書きません。

| 画面・状態 | 見出し | 主な操作 |
|---|---|---|
| `/mail` / form | ツクハコを使い始めるヒントを、メールで | 確認メールを受け取る |
| `/mail/check` / check | 確認メールをご確認ください | メールを確認する。未着時は修正・再送 |
| `/mail/confirm` / confirm | メールの受け取りを始めますか？ | 登録を確定する |
| expired | 確認リンクの有効期限が切れています | 新しい確認メールを受け取る |
| used（現在も購読中） | このリンクでの確認は済んでいます | 追加確認は不要 |
| unsubscribed（古い確認リンク） | メールの配信は停止されています | 再び希望する場合は登録画面へ |
| invalid | このリンクは使えません | 登録画面へ戻る |
| complete | 登録が完了しました | 使い始めるガイドを読む |
| `/mail/unsubscribe` / unsubscribe | メールの配信を停止しますか？ | 配信を停止する |
| 解除完了 | 配信を停止しました | 追加操作は不要 |

登録画面には、初回3通・その後週1回程度・休む週もあること、任意登録、いつでも解除できること、送信者と連絡先、プライバシーへのリンクを表示します。同意欄の初期値は未選択です。

受付後は、アドレスの登録有無を明かさない一般化した文言です。入力値を表示するためにURLやHTMLへ埋め込むことは求めません。再送後は新しいメールを使うよう案内します。再送の制限中に表示する待ち時間は、Bの実際の状態から決めます。

確認ページをGETで開くだけでは購読を確定せず、本人の「登録を確定する」操作で確定します。古い使用済みリンクは、現在の購読状態を見てused/unsubscribedを出し分けます。「確認済み」という過去の事実だけで、解除後も購読中と表示しません。

解除ページのGETも状態を変えません。ブラウザ画面は「配信を停止する」から解除をPOSTします。配信サービスの機械的なワンクリック解除POSTには、この確認画面やログインを要求しません。

解除完了には、未送信の案内を止めたこと、購入済み商品の受取には影響しないこと、すでに送信手続きが済んだメールが届く場合があることを表示します。永久バウンス・苦情などの抑止は、登録入力や古い確認リンクだけで解除しません。

設定待ちや外部送信しない説明は運営用ローカルプレビューで表示します。購入者向け画面にAPI、キュー、DBなどの実装語を出す必要はありません。
