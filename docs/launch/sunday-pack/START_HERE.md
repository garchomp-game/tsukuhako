# F2の最初の画面を表示する

ツクハコ **0.4.4** 用・ガイド **2026-10-25-r1**。検証協力者向けの配布候補です。

「Dev Containerを使う前の準備で迷う」方へ。今回は **F2（Next.js）を生成し、初期処理の正常終了を確認して、ブラウザに最初の画面を表示する** ところまで進みます。ほかの構成を比較する必要はありません。変更・復元は、表示できた後の任意の練習です。

## 受け取ったもの

- このガイドのZIP：展開して、この `START_HERE.md` を開きます。案内5本と `manifest.json`、`SHA256SUMS` の7ファイルです。ZIPの中にアプリ本体はありません。
- 自分のOS用アプリセット：製品1本と `START_HERE.txt`、`manifest.json`、`SHA256SUMS` の4ファイルです。Linux用とWindows用を混ぜません。アプリセットの案内revisionは **2026-10-22-A** です。

案内だけ届いた場合は、受け取った経路でアプリセットを確認してください。購読登録やログインを追加しても、アプリが取得できるようになる仕組みではありません。

## 対象と確認できている範囲

| PC | この候補での扱い |
|---|---|
| Linux x64 | Linux Mint 22.3の**既存開発環境**でF2の一経路を確認。未準備PCからの導入・他のLinuxでの完走は未確認 |
| Windows 11 x64 | **通常ユーザー・実WSL/F2は未確認**。検証協力用の候補。未署名exeのServer 2022 CIによる補助確認は、Win11実機の確認とは異なる |
| macOS / ARM | この配布候補の対象外 |

所要時間はネット接続やPCの状態により変わります。スマートフォンで案内は読めますが、操作は対象のPCで行います。

## 必要な準備と、最初の操作

アプリを開いて教材を読む段階では、PC側のNode.js・アカウント登録は不要です。F2を動かす段階で、ネット接続、Docker、VS Code、MicrosoftのDev Containers拡張が必要です。Windowsでは、さらにWSL 2・WSL拡張とDocker Desktopの連携を使います。

**次の一操作：アプリセットの `START_HERE.txt` を開き、自分のOSの照合・導入手順でツクハコを起動してください。** 警告で止まったときは保護を解除せず、[困ったとき](TROUBLESHOOTING.md)へ進みます。

起動できたら [FIRST-RUN.md](FIRST-RUN.md) の1番から順に進みます。途中から再開する場合も、最初に現在地を確認できます。

| 今の状態 | 次に開く案内 |
|---|---|
| アプリを開けた／準備不足を知りたい | [FIRST-RUN](FIRST-RUN.md) |
| 途中で止まった／前の続きから再開したい | [TROUBLESHOOTING](TROUBLESHOOTING.md) |
| 最初の画面が表示できた | ここで今回の目標は達成。[NEXT-STEP](NEXT-STEP.md) は任意 |
| 止まった場所や迷った点を残したい | [FEEDBACK](FEEDBACK.md)。氏名・メール・秘密は不要 |

このガイドの `START_HERE.md` と、後で生成される**プロジェクト内の `START_HERE.md`** は別物です。後者には、あなたが選んだ保存先とブラウザ用URLが入ります。
