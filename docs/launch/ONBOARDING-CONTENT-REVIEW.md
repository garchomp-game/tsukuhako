## 検査方法

[原稿検査](validate-content.mjs)は、メールのfrontmatter/リンク宣言/予約変数/公開と非公開の分離、実製品の6表示名、正本のSHAと相互リンク、共有見出しの順序、生成済みsetupの見出しへの到達を調べます。`--output` を省略するとファイルを書かず、指定した場合も既存の証拠を上書きしません。

統合リポジトリで教材生成後に実行します。

```sh
node docs/launch/validate-content.mjs
```

新しい監査を保存する場合は、まだ存在しないファイル名を指定します。

```sh
node docs/launch/validate-content.mjs --output docs/launch/evidence/content-audit-onboarding-r4.json
```

分担中の読取照合では `--product-root` と `--curriculum-root` で、統合側の製品ソース・教材を指定できます。検査がそれらを書き換えることはありません。今回の結果は[静的監査JSON](evidence/content-audit-onboarding-r4.json)に記録しました。**86/86項目PASS**です。正本内の相互・見出しリンク56件、生成済みsetupへの見出しリンク9件、共有する工程見出し9件を含みます。正本5本とmanifestのSHA6件も一致しました。旧 `evidence/content-audit.json` は2026-10-22時点の証拠として保持します。

Bの取込は、実データを持たない一時フォルダーで既存 `web/scripts/import-content.mjs` とサンプル設定を使って確認します。確認後は一時フォルダーを削除します。[取込fixture結果](evidence/mail-content-fixture-onboarding-r4.json)は **6/6項目PASS** です。5通の版・draft状態、4ガイド本文の一致、非公開情報の除外、空の公開リンク設定、署名分離、宣言リンクの一致を確認しました。
