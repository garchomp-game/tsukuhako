# {{name}}を作る前に困ったとき

まだファイルの作成は完了していません。サンプルの起動やデータベースの復旧は、作成後の手順です。上の「作る画面へ戻る」で、選んだ構成と入力の続きを開けます。

## 準備を確認する

<!-- os-preparation-start -->
OSの確認結果がまだない場合は、自分のPCに合う準備手順を選んでください。

[Linuxの準備](lesson:setup/linux) · [Windowsと選択したWSLの準備](lesson:setup/windows) · [macOSの参考手順](lesson:setup/macos)
<!-- os-preparation-end -->

LinuxではDocker・VS Codeが未準備でも、保存先の条件がそろえばファイルを作れます。起動前に不足を解消します。Windowsでは、使うWSLを選び、そのWSLのヘルパーの準備を終えてから進みます。OSを確認できない間は、別のOS用コマンドを実行せず、準備チェックをやり直してください。

構成選択で「{{name}}」を確認し、「保存先を決める」を押すと入力画面が開きます。

## 保存先を確認する

「親フォルダ」には、すでに存在し、自分が書き込める場所を選びます。「新しいフォルダ名」には、まだ存在しない名前を入力します。Windowsは選択したWSLのホーム配下を使います。

同名のフォルダーがある場合は中身を確認します。作成済みなら、そのフォルダーのSTART_HERE.mdから再開します。新しく作る場合だけ別の名前を選びます。既存フォルダーを消して解決しないでください。

入力を直して「作成内容を確認」を押します。エラーが残る場合は表示された理由と対処を確認します。

## 作成内容を確認する

構成名・保存先・ポートを確かめます。変更するときは「戻る」で入力へ戻ります。使用中のポートは詳細設定で別の値へ変更し、再度「作成内容を確認」を押します。別のプロジェクトを勝手に停止しません。

メモを保存するWeb画面はDB関連の連続4ポートも確認します。「ファイルを作る準備」が確認済みになったら「プロジェクトを作成」を押します。

## 作成に失敗したとき

エラーに表示された理由と対処を読みます。保存先・空き容量・書き込み権限など、指摘された項目を確認して入力へ戻ります。フォルダーができている場合は中身を確認し、作成済みのファイルや.envを上書き・作り直ししないでください。原因が分からなければ、構成名・操作した段階・エラー文を記録します。.envの値や秘密情報は添えません。

作成完了が表示されるまでは、サンプルの起動コマンドやDBの初期化を実行しません。

## 作成した後に困ったとき

作成完了画面の主ボタンから、今回の保存先とポートを使う手順へ進みます。アプリを閉じた場合は保存先のSTART_HERE.mdを開きます。

[{{name}}の作成後の復旧資料]({{recovery}})は補助資料です。標準設定の例があるため、今回の値は保存済みの案内で確認してください。
