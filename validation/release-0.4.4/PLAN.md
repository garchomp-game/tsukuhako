# 0.4.4 着手計画・合否条件

2026-10-22。起点は main / 14a53a6e930ce507c9ab390f549b6e91e32067a1、変更なし。製品0.4.3から0.4.4へ進める。

1. 既存0.4.3配布物の通常幅・狭幅・200%を再現し、スクロール構造と読書保存を記録する。配布経路・Windows導入処理は独立して調べる。
2. Readerを改善し、読書位置・章/見出し移動・ヘルプ復帰・F2生成/S2学習の独立性を回帰確認する。本文末尾と前後章ボタンに届くこと、キーボード操作、幅変更時の位置保持を合格条件とする。
3. OS別に製品ファイル1個・START_HERE・manifest・SHA256SUMSの配布フォルダを作る。製品内の実行依存/教材/テンプレート/ライセンスの検査を維持し、日本語・空白パスで照合する。未決の取得先は制作側文書に分離する。
4. 手動Windows CIで同じexeを導入し、実導入先からの通常起動とrenderer/教材を確認、実際に作られた読書データの削除前後SHAを照合する。各段階にタイムアウト、失敗時ログ、限定した後片付けを設ける。Windows Server管理者CIとWin11通常ユーザーは区別する。
5. テスト・内容検査後に製品commitをpushし、そこから両OSをビルドする。最終Linux配布物でReader一連操作とF2生成→初期構成正常終了→表示→変更→復元を実機確認する。
6. 証跡と結果表、OS別ファイル情報、取得権限・期限、残作業、5〜10分の試用手順を別の証跡commitでpushする。

証拠は REAL_HOST / CI / FIXTURE / STATIC / NOT_RUN を明示。公開・新規契約・共有権限変更は行わない。既存Docker・過去配布物・過去証跡を維持する。Mac/ARM、未導入PC、初心者本人、Win11/WSL/Docker開発経路は実施していない限りNOT_RUN。
