ツクハコ 0.4.4 — 配布案内ドラフト
最初にこの START_HERE.txt をお読みください。

対象：Windows 11 x64（Intel/AMD 64bit）。Windows ARMは対象外。
確認範囲：Windows Server 2022 CIの管理者権限を持つrunnerで、同じexeのユーザー単位導入、導入先からの起動・教材表示、削除、隔離した実読書データのSHA保持を確認。Win11通常ユーザー・WSL/DBの保持は未確認。
macOS版は今回ありません。

1. 受け取ったファイルを確認する
このOS用フォルダの4ファイルを同じ場所へ保存します。GitHub Actionsから取得する場合はダウンロードZIPを一度展開します。
・START_HERE.txt（この案内）
・tsukuhako-windows-x64-0.4.4-setup.exe（製品）
・manifest.json（版・元commit・ハッシュ・検証範囲）
・SHA256SUMS（製品・案内・manifestの照合値）
提供元を確認し、必要に応じてハッシュを照合します。
PowerShellで受取フォルダを開き、Get-FileHash .\tsukuhako-windows-x64-0.4.4-setup.exe -Algorithm SHA256 のHashをSHA256SUMSの同名行と比較します。

2. 起動する
tsukuhako-windows-x64-0.4.4-setup.exe を普段のWindowsユーザーで実行します。導入後はスタートメニューの「ツクハコ」から起動します。未署名の検証用です。OSの保護を無効化せず、警告で止まる場合は警告内容を記録して提供元に確認してください。CIでの成功はWindows 11の初回警告・WSL動作の確認ではありません。

3. まず教材を読む
アプリ上部の「学ぶ」を開きます。「目次を開く」（広い画面では「目次へ移動」）からF2の「最初の一歩」を選べます。狭い画面では目次と本文を切り替えて読みます。目次内でEscを押すと本文へ戻ります。
表示拡大：Ctrl と +（または =）で25%ずつ、最大200%。Ctrl と - で縮小、Ctrl と 0 で100%へ戻します。「困ったとき」から「学んでいた章へ戻る」で元の位置へ戻れます。
教材の閲覧にアカウント登録やホストNode.jsは不要です。

4. 開発準備を確認し、F2を生成する
「作る」の準備チェックからOS別の準備手順へ進みます。初回のDockerイメージ、npm依存、VS Code拡張等の取得にはネット接続が必要で、時間は環境により変わります。
Windows版VS Code、WSL/Dev Containers拡張、通常ユーザーのWSL 2、同じWSLのDocker Desktop Integrationを教材に沿って準備します。ツクハコで通常のWSLを選び、準備チェック後にWSL用ファイルを準備します。rootやdocker-desktopを開発先にしません。保存先は選択WSLのHOME配下の既存親フォルダと新しいフォルダ名を指定します。
アプリのインストール・展開先にプロジェクトを保存せず、既存フォルダに重ねて生成しません。生成後は完了画面の「VS Codeで開く」へ進みます。
Reopen in Containerの後、構成ターミナル本文の「準備完了」と初期構成の正常終了を待ちます。その後に新しいターミナルで npm run dev を実行します。接続バッジやConfiguringタブだけで完了と判断しません。
今回の保存先・ポート・変更と復元の手順は、生成先の START_HERE.md に記録されます。この配布案内はアプリを受け取る入口、START_HERE.mdは生成したプロジェクトの操作手順です。生成済みプロジェクトは自動更新されません。

5. 閉じる・再開する・削除する
アプリを閉じても生成プロジェクト・VS Code・Dockerは残ります。読書位置は保存しますが、入力内容・診断・生成完了画面は再起動でリセットされます。開発を再開するときはVS Codeで生成先の START_HERE.md を開きます。不要になった開発サーバーやコンテナの停止は教材の手順で行います。
Windowsの「インストールされているアプリ」から本体を削除できます。設定上、生成先・WSL・Dockerデータ・WSL内 ~/.tsukuhako-helper・読書設定 %APPDATA%/tsukuhako は削除しません。実WSL/DBの削除後保持とWindows 11実機は未確認です。CIの保持確認は隔離した読書設定ファイルの範囲です。

困ったら、行った操作・OS・表示されたメッセージを記録してください。診断ログを渡す前にパスや秘密情報が残っていないか確認します。今回の配布案内はドラフトです。
