## 結論

**共通コアと生成処理は再試験に合格。対話CLIの「戻る」操作に1件の修正推奨がある。Linux GUIはソースと提出証拠を確認できたが、配布バイナリは未受領で、このレビューでは起動していない。**

この成果物を次の作業の基点として受け取ってよい。配布候補として確定する前に、下記R1を修正する。既存テンプレートを作り直す必要はない。

実装側の「G01〜G15 PASS」は記録されたLinux環境・操作範囲での報告として読む。本レビューで再実行した範囲と同一ではなく、R1により対話CLIの入力保持は一部未達と判定する。

## 3. R1：対話CLIで戻ると詳細設定が無効になる

重要度：中。生成不能や既存ファイル破壊ではないが、入力保持の要件とREADMEに合わない。

箇所：
- `generator/src/cli/wizard.mjs` のadvanced入力定義
- 同ファイルのrequest組立て（advancedがyの場合だけname/port/dbBaseを渡す部分）

### 再現手順

1. wizardでF2を選ぶ。
2. 詳細設定をyにし、識別ラベルをcustom、ホストポートを3409にする。
3. 確認画面で `:back` を入力する。
4. 親フォルダ・新しいフォルダ名・詳細設定をすべて空入力で進める。

|項目|戻る前|空入力で進んだ後|
|---|---|---|
|アプリポート|3409|3001（既定値）|
|識別ラベル|custom|指定なし|

advancedの表示が常に `[y/N]`、空入力の解釈が常にnのため。値自体はstateに残るが、生成requestから除外される。

変更結果は再確認画面に表示されるため、確認なしで直ちに誤生成されるものではない。

**暫定回避：戻った後も詳細設定でyを選ぶ。** customと3409が再び既定値に現れ、空入力で維持できることを実PTYで確認した。

### 修正条件

- 戻った時点のadvancedの値を表示上・空入力時の既定値にする。
- 利用者が明示的にnを選ぶ操作は残す。
- 「詳細設定あり→確認→戻る→変更なし→再確認」でラベルとポートが保持されるPTY回帰試験を追加する。
- 同じ入力保持要件の範囲で、用途・Next/Viteの選択も戻った際に現在値を既定値として扱えているか確認する。こちらは今回、別の実PTY不具合としては確定していない。
- 生成前中止ではファイルを書かないことを維持する。

提出済みのPTY試験は詳細設定nのケースだったため、この操作は検出されていなかった。

## 4. 提出された実行証拠の確認

受入G01〜G15に紐づく証拠ファイルと21件のコマンド記録・ログが存在することを確認した。

- GUI：実ウィンドウの戻る・入力修正・生成、worker再試行、reload後のplan無効化、6構成のCLIとの一致、ホストNode/Docker/Code不在時の挙動が記録されている。コード・試験スクリプト・結果・画面の間に今回の確認範囲で矛盾は見つからなかった。
- F2：最終単独CLIからの生成、Dev Container CLIによる起動、check、HTTP試験1件、画面遷移・入力・クリア・編集反映の成功記録がある。
- S2：最終単独CLIから新規ID・新規DBで生成し、check、単体5件、DB検査、HTTP2件、Unicodeメモの保存・更新・再読込・削除の成功記録がある。
- 検証資源：対象コンテナ停止・試験ポート解放、volume/image保持、無関係なコンテナを維持した記録がある。

これらは実装側の実行記録を確認した結果。今回こちらで同じ実環境を再現したという意味ではない。S2の停止・再開後の保持については、実装レポートどおり今回分と0.1.1の過去記録を区別する。

## 6. 軽微な差分と公開前に決めること

- 診断のタイムアウトは現在FAILと表示する。文言は「時間内に確認できませんでした」で正確、生成も妨げない。設計の厳密な区分に合わせるならNOT_CHECKEDにできるが、今回の必須修正には含めない。
- GUIとCLIに「明鏡」という名称が使われている。要件上、製品名は未決定。教材サイトと独立したおとかさんの製品として、公開前に名称を決める。今回のローカル検証を止める事項ではない。
- GUIの容量削減、Windows GUI、自由な構成組合せは、今回の修正完了条件へ追加しない。
