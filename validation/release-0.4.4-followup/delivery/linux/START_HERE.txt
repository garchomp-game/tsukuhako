ツクハコ 0.4.4 — 配布案内ドラフト
最初にこの START_HERE.txt をお読みください。

対象：Linux x64（Intel/AMD 64bit）。確認対象はLinux Mint 22.3。ARMは対象外。
確認範囲：Linux Mint 22.3 x64の既存開発環境で、引数なし通常起動、教材の100%・狭幅・200%表示、読書位置の復元、F2生成→Dev Container初期構成の正常終了→表示→編集→復元→再開を確認。未導入PC・他のLinuxは未確認。
macOS版は今回ありません。

1. 受け取ったファイルを確認する
このOS用フォルダの4ファイルを同じ場所へ保存します。受取先からZIPで届いた場合は、外箱のZIPを一度展開します。
・START_HERE.txt（この案内）
・tsukuhako-linux-x64-0.4.4.tar.gz（製品）
・manifest.json（版・元commit・ハッシュ・検証範囲）
・SHA256SUMS（製品・案内・manifestの照合値）
提供元を確認し、必要に応じてハッシュを照合します。
受取フォルダのターミナルで sha256sum -c SHA256SUMS を実行すると3ファイルを照合できます。

2. 起動する
tsukuhako-linux-x64-0.4.4.tar.gz をホーム内など書き込み可能な場所に展開します。展開後の tsukuhako-linux-x64-0.4.4 フォルダの中にある tsukuhako が実行ファイルです。resources内は操作しません。
ターミナルなら受取フォルダで次を順に実行できます。
  tar -xzf "tsukuhako-linux-x64-0.4.4.tar.gz"
  "./tsukuhako-linux-x64-0.4.4/tsukuhako"
一般ユーザーで起動します。sudoや --no-sandbox は使いません。日本語・空白を含むパスは上のように引用符で囲みます。

3. まず教材を読む
アプリ上部の「学ぶ」を開きます。「目次を開く」（広い画面では「目次へ移動」）からF2の「最初の一歩」を選べます。狭い画面では目次と本文を切り替えて読みます。目次内でEscを押すと本文へ戻ります。
表示拡大：Ctrl と +（または =）で25%ずつ、最大200%。Ctrl と - で縮小、Ctrl と 0 で100%へ戻します。「困ったとき」から「学んでいた章へ戻る」で元の位置へ戻れます。
教材の閲覧にアカウント登録やホストNode.jsは不要です。

4. 開発準備を確認し、F2を生成する
「作る」の準備チェックからOS別の準備手順へ進みます。初回のDockerイメージ、npm依存、VS Code拡張等の取得にはネット接続が必要で、時間は環境により変わります。
Docker Engine + Compose、VS CodeとMicrosoft Dev Containers拡張を教材に沿って準備します。「作る」でF2を選び、「保存先を決める」でホーム内など既存の親フォルダと新しいフォルダ名を指定します。
アプリのインストール・展開先にプロジェクトを保存せず、既存フォルダに重ねて生成しません。生成後は完了画面の「VS Codeで開く」へ進みます。
Reopen in Containerの後、構成ターミナル本文の「準備完了」と初期構成の正常終了を待ちます。その後に新しいターミナルで npm run dev を実行します。接続バッジやConfiguringタブだけで完了と判断しません。
今回の保存先・ポート・変更と復元の手順は、生成先の START_HERE.md に記録されます。この配布案内はアプリを受け取る入口、START_HERE.mdは生成したプロジェクトの操作手順です。生成済みプロジェクトは自動更新されません。

5. 閉じる・再開する・削除する
アプリを閉じても生成プロジェクト・VS Code・Dockerは残ります。読書位置は保存しますが、入力内容・診断・生成完了画面は再起動でリセットされます。開発を再開するときはVS Codeで生成先の START_HERE.md を開きます。不要になった開発サーバーやコンテナの停止は教材の手順で行います。
本体を終了してから展開した tsukuhako-linux-x64-0.4.4 フォルダを削除できます。別に保存した生成先、Dockerデータ、読書設定（通常 ~/.config/tsukuhako、XDG_CONFIG_HOMEを指定していればその配下）は残ります。

困ったら、行った操作・OS・表示されたメッセージを記録してください。診断ログを渡す前にパスや秘密情報が残っていないか確認します。今回の配布案内はドラフトです。
